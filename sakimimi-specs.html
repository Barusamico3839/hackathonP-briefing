共通要件 — サキミミとは何か

マイクとミキサーの間にXLRで挟むだけの小さな箱。現場の「ハウリングの鳴きグセ」をその場で学習し、鳴る前の予兆で先回りする。

🎯 2つのモード（=製品の物語）

🛡️ 見守りモード🔥 ブーストモード
使う場面校長先生の朝礼・礼拝・集会所バンド練習・小さいライブハウス
音への介入基本は素通し。予兆時だけゲインをスッと下げる鳴きグセの周波数だけ高Qナローノッチ（狭い範囲だけ深く絞る。幅広EQではない）で削り、そのぶんボーカルを上げる
価値「キーン」が二度と鳴らない安心ボーカルが通常のハウリング限界を超えて+8dB級で立ち上がる
対応する作成物作成物②（①PC開発機 7/30通話で①中止 → 実験①のPCリグで検証後、②で実装）作成物②（確実ルート・提出デモ）・作成物③（挑戦ルート）（部品購入見送り）

📋 機能要件（FR）と非機能要件（NFR）

ID要件目標値・備考
FR-1ハウリング予兆の検知鳴き始め（リンギング成長）を可聴レベル到達の前に検知。リードタイムは実験①で実測し目標値を確定（まず200ms以上を仮目標）
FR-2ゲイン制御0〜-12dB。0.5dBステップを数十msでランプ（クリック/ジッパーノイズなし）。「介入したのに耳障り」はコンセプトの自殺
FR-3その場学習ハウリング波形=自動ラベルの教師あり学習＋ボタンによる誤検知矯正（なで 7/30なでUI廃止）。会場ごとの鳴きやすい周波数を記憶
FR-4高Qナローノッチ（ブースト）Q≈10〜100（1/10〜1/60オクターブ幅）の狭帯域ノッチ×1〜3から開始・拡張上限の目標はバンク化で10〜20本・可変式（7/30夜MTGでひかるの理想を確認。4〜8本から引き上げ。ADAU1701なら部品変更ゼロ・7/31資源計算で検証済み→再検証）・周波数可変（300Hz〜6kHz目安）・深さ0〜-18dB可変・動作中書換。1〜3バンドEQ（7/30修正: 幅広EQでは声ごと削れてブーストの余地が出ない。狭く深く絞るから声が無傷のまま限界ゲインが上がる）
FR-5フェイルセーフ電源断=物理直結で音は通る（リレーバイパス。②で搭載）
FR-6教示UI誤検知→「今のは違う」ボタン/スイッチを押して矯正（頭をなでる 7/30廃止・タッチセンサ不要に）。外装・キャラ設計はけいと領分
NFR-1主音路レイテンシ①往復10ms以下（PC・WASAPI排他/ASIO小バッファ・実測必須。0msアナログ 7/30 PC化）／②2ms以下（DSP実測）／③0ms（アナログ）。根拠: ウェッジモニタ10msまで知覚OK（Lester & Boley 2007）
NFR-2ノイズ・ハム（②の箱）金属ケース・Pin1最短シャーシ落とし・電池駆動でグラウンドループ物理排除・スター接地（①はIFの品質に乗るので対象外）
NFR-3電源（②の箱）006P 9V×2（±9V）+3.3V系。デモ2時間連続動作以上（①はPC/USB給電・電池要件なし）
NFR-4安全ミキサーのファンタム+48V流入に耐える（出力カップリング63V耐圧+ブリード抵抗）
NFR-5入出力入力: ダイナミックマイク（XLRバランス・v1はファンタム非対応）／出力: ライン +4dBu級（インピーダンスバランス）
v1で「やらない」と決めたこと（スコープ外）
  • コンデンサマイク対応（ファンタム電源供給）— 学校のワイヤレス・SM58系・カラオケマイクは全部ダイナミックなのでv1不要
  • 音質の追求 — ハッカソンでは追わない（突っ込まれたら「製品化ではADC/DAC構成を検討」と回答）
  • 完全ディスクリートの可変アナログノッチ — 3調査一致で「商用でも高級品の領域・DIY完走例なし」。やらない
  • 複数マイク同時（マルチチャンネル）— 物語としては語るが実装は1ch
共通の土台=2回路構成。音が通る「主音路」と、音を聴いて判断する「分析路」を分ける。分析路（ML63Q2557: 12bit ADC→HW-FFT→ELM学習）は3つの作成物で共通・作り直しなし。進化するのは主音路だけ。
①

作成物① 見守りモード機（PC+オーディオIF版） 7/30通話: 作らない方向に

🔄 7/30通話（ひかる×けいと）: 作成物①は「作らなくてもいい」となり、買い物も②用のみに絞った。ただしこのセクションのPC+IF環境は消えない——実験①（ハウリング予兆の観測=本当のGo/No-Go）のリグ、およびML63Q2557連携の開発環境としてそのまま使う。「作成物」として仕上げないだけで、下記の設計メモ・着手順序は実験リグの手順として有効。

（記録: 7/30夜時点の旧計画 = 主音路を自作アナログ（INA217+PGA2311）→ 手持ちのオーディオIF+PCソフトに変更し、①単体で劇場型デモを成立させる案だった）

       │ XLR

  [オーディオIF（所持済み）: 内蔵マイクプリ + AD] ── USB ──┐

設計メモ（レベル合わせ・レイテンシ・ソフト）
  • ゲイン制御はソフトで実装: 0.5dB刻みを数十msでランプ（クリック/ジッパーノイズなし）。FR-2の要件は変わらず実装先がPGA2311→コードに変わっただけ
  • 分析路への給音: PCがドライ信号（介入前）のコピーをIFの余り出力（ヘッドホンout可）へ常時出す → 抵抗分圧で±1V級→1.65V中点バイアス→直列100Ω〜1kΩ保護→3.3V系ADC。受動部品数点（秋月の抵抗袋でカバー）+手持ちIFの端子に合うプラグ1個だけ
  • レイテンシ: WASAPI排他/ASIO・小バッファで往復5〜10msが相場。ボーカル/ウェッジのGood閾値10ms以内を実測で確認（NFR-1）。スピーチ用途デモなら十分
  • ML63Q2557→PC: キットのUART/USBシリアル経由でゲイン指示（プロトコルは「周波数・dB量」のテキスト1行で十分。②でそのままI2C safeloadに置き換わる）
  • 審査上の位置づけ: ①は「最速で全体を動かす開発機」。提出デモ・展示は②（専用ハード）で行い、①は開発過程として見せる（PCを主役に見せるとSolist-AI活用度の物語が薄まるため）

✅ 完成条件（DoD）と受け入れテスト

  • マイク→IF→PC→ミキサーのパススルーが安定動作（音切れ/xrunなし・往復レイテンシ実測10ms以下）
  • ML63Q2557からのシリアル指示で-3dB → クリック音なしでスッと下がる（録音して波形確認）
  • 分析路（IF余り出力→分圧→ML63Q2557）でFFTスペクトルが取れて、スイープ音のピーク周波数を正しく追える
  • ゲインを上げてわざとハウらせ→予兆検知→自動で-3dB→鳴かない、のE2Eデモが1回成功する
着手順序（推奨・買い物の到着を待たない）
  • 1. PCパススルー+ソフトゲイン制御を動かす（sounddevice・手持ちIF）→ レイテンシ実測
  • 2. 同じ環境で予兆観測実験①（ゲイン漸増→鳴く直前のスペクトル録音→elmkitでELM学習可能性判定）＝本当のGo/No-Go
  • 3. キット到着後: ML63Q2557に分析路を移植（分圧+バイアスだけブレッドボード）→ シリアル連携でE2E
  • 旧①のアナログ入力段（プリ+ケース）は②の部品として8月W2から着工
②

作成物② 本番機・ルートA（低遅延DSP） 確実寄り・提出デモはこれ

①のPC主音路を専用ハード（自作マイクプリ + ADAU1701 DSPボード）に置き換えて箱に収める（7/30改: ①がPC化したので、見守りモードのゲイン制御もブーストの高Qナローノッチも②が1台で担当）。係数はML63Q2557からI2Cで動作中に書き換える。Qは係数のパラメータにすぎないので、狭帯域化しても部品・構成は変わらない。遅延は約1ms=マイクから34cm離れたのと同じ。

ブロック図（①からの差分）

  [マイクプリ SSM2019BNZ +30dB]（自作・旧①用に選定済みの部品をここで使う）
       │
       ├──────────────────────────────────┐
       │ 主音路（PC→専用DSPに変わる・約1ms） │ 分析路（①と同一・変更なし）
       ▼                                  ▼
  [ADAU1701ボード: AD→高Qノッチ×3+ゲイン→DA]   [ML63Q2557]
       │                ▲                      │
       │                └──── I2C(safeload) ───┘
       ▼                 「2.1kHzだけQ30で-12dB」を動作中書換
  [リレー物理バイパス] → ミキサーへ
   電源OFF=リレーが直結側に落ちる（壊れても音は通る）
開発フロー（SigmaStudio）
  • 1. SigmaStudio（無料・Windows）で高Qノッチ×3+ゲインのブロック図を描く（300Hz未満の高QはダブルプレシジョンbiquadブロックでOK）
  • 2. 書込機でボードのEEPROMへ書き込み（セルフブート化）
  • 3. ML63Q2557からI2C safeloadでbiquad係数を動作中に書き換え（Arduino向けライブラリの前例あり: MCUdude/SigmaDSP）
  • 4. ノッチの本数・周波数・Q・深さ・メイクアップゲインは係数書換だけで自由

✅ 完成条件（DoD）

  • ピンクノイズを通してRTA（スマホアプリ可）でノッチが指定周波数に出ることを確認（高Qで幅が狭いのでRTAは高分解能設定 or サインスイープで測る）
  • 動作中にI2Cでノッチ周波数を移動してもノイズ・音切れが出ない
  • ループバック実測でレイテンシ2ms以下
  • 🔥ブーストデモ: わざとハウリングループを組み、ノッチ+メイクアップでボーカルが従来限界+6dB以上まで上げられる（実測値を記録=審査の実測データ）
  • 電源断でリレーが落ちて音が素通しになる
③

作成物③ ブースト機・ルートB（真アナログ維持） 挑戦

主音路をアナログに戻し、ノッチは横道（サイドチェーン）で作って「引き算」する。原音はオペアンプ1〜2段しか通らない。業務用がほぼ全デジタルの中で「主音路は真アナログ」は審査上の差別化になる。時間が余ったらの勲章枠。

ブロック図（②からの差分）

  [マイクプリ INA217 +30dB]
       │
       ├──────────────┬───────────────────┐
       │ 主音路(アナログ) │ サイドチェーン       │ 分析路（①と同一）
       │              ▼                   ▼
       │      [SCFバンドパス LMF100/MAX7490]  [ML63Q2557]
       │       f0 = クロック÷100 ◄─ PWM ──────┤ 周波数指示・校正不要
       │              ▼                   │
       │      [深さk = デジポット MCP41010] ◄─ SPI ─┤
       ▼              │                   │
  [反転加算器: 原音 − k×BP] ◄┘          │ -5dB ⇔ k≈0.44
       ▼                                  │
  [PGA2311（①のまま復活）] ◄─── SPI ──────┘
       ▼
  [出力バッファ] → ミキサーへ
SCF実装の注意（先人の踏んだ穴）
  • クロックフィードスルー対策: f0下限300Hz（fclk≥30kHz）・サイドチェーン入力に固定LPF(10kHz)1段
  • LMF100のMode1ノッチ直取りは深さ固定 → BP出力+反転加算の構成を採る（深さ可変・深さ0で完全素通し）
  • SOICパッケージのハンダ（変換基板）・単電源バイアスが初心者ポイント
  • ⚠️ ML63Q2557のPWM元クロック・独立ch数は未確認 → キット到着後最初に確認（3バンド化の前提）

✅ 完成条件（DoD）

  • PWMクロックでノッチ中心周波数が数式どおり（f0=fclk/100）に動く（RTAで確認）
  • デジポットで深さ0（完全素通し）〜-12dBが連続可変
  • クロックノイズが聴感で気にならない（300Hz以上運用+LPFで）
  • ②と同じブーストデモがアナログ主音路で再現できる

リスク表（発生したらどうするか）
  • Solist-AIキットが届かない → 全工程の律速。見積電話が最優先。届くまでは分析路をPC+オーディオIF（所持）で代替開発
  • 予兆が学習可能な特徴量にならない → 「鳴ってから0.1秒で止める」に軸足を移す（それでも既存品より速い+現場学習は残る）
  • ハム・ノイズが取れない → 電池駆動徹底・ケース/接地見直し。最悪デモはノイズの少ない構成に絞る

実験①（ハウリング予兆の観測）が全ての起点。マイク+スピーカー+オーディオIF（全部所持済み）でループを組み、ゲインを徐々に上げながら録音→鳴く直前のスペクトル変化を可視化。部品が届く前の今週末にもできる。
